# Spec #37: Discover, the React app for building cohorts over the REST API

Part of #23. `docs/ARCHITECTURE.md` decisions 1, 2 and 6; page design in
`dashboard/COHORT_DISCOVERY.md` §3.3. Builds on #34 (the cohort module) and #35 (`genomics-app`,
spec `docs/specs/35-genomics-app-fastapi-rest-and-mcp-over.md`). Label: `review:ux`.

All examples are synthetic. Gene symbols, OncoTree codes and marker names are public vocabulary;
no real counts appear.

## Goal

A React + TypeScript single-page app in `web/` (Vite, bun), built to static files that
`genomics-app --static web/dist` serves same-origin behind the same login as `/api/*`. A user
builds a cohort definition by clicking (population chips, criterion cards, a typeahead "Add
criterion"), sees the answer (cards with a named denominator, funnel, Accrual / Breakdown / Pivot /
Data notes tabs, loosen suggestions under the floor), steps through versions, and shares the cohort
by link. The browser holds only the definition and edits it with operations through one transport
seam; every number on screen is one the API returned, already suppressed.

Done when, from the tailnet dev server (`genomics-app --auth password --host <tailnet-addr>
--static web/dist`), a user can build a cohort by clicking, see the funnel, accrual, breakdown,
pivot and data notes, and share it by link; and CI runs the web checks.

## Non-goals

- No assistant: the right-hand column is reserved and empty (chat is phase 3, decision 9).
- No saved cohorts, server-side versions or `/c/<cohort_id>` short links (Postgres issue,
  decision 7). Versions live in `localStorage`; the share link carries the definition.
- No Compare, Feasibility statement or Request data buttons (phase 2, §4 of
  `COHORT_DISCOVERY.md`).
- No phase 2 controls: no include / exclude / tested-negative toggle, no "same report" lock, no
  `sequence` or `data` criteria. The module rejects them (#34), so the UI does not offer them.
- No drag-to-reorder of criterion cards: there is no reorder operation in the module. The funnel
  follows the order criteria were added.
- No MCP App transport (decision 10). Only the `fetch` implementation of the seam.
- No change to `dashboard/` (the public Observable site and its `cohort.md` stay until decision
  12 retires them), `cohort_api.py`, `server.py`, `authen.py`, suppression, the compiler, the
  mart or `deid`.
- No systemd unit, Traefik route, `tailscale serve` or deploy.
- No data change: no schema, table or column; `research_id` and `report_id` are untouched.

### Generated types (decision 1: the schema is the frontend's types)

`web/openapi.json` is `json.dumps(app().openapi(), indent=2, sort_keys=True)` plus a newline,
committed. `web/src/api.gen.ts` is generated from it and committed. Two guards keep them honest:

- Python, `tests/test_app.py::test_openapi_snapshot`: `json.loads((ROOT / "web" /
  "openapi.json").read_text()) == app.app().openapi()`, failing with "run `cd web && bun run
  gen`". A backend model change without regeneration fails pytest.
- Web, `bun run typecheck`: `openapi-typescript ... --check` fails if `api.gen.ts` is stale
  against `openapi.json`, then `tsc --noEmit` type-checks the app against it.

`openapi-typescript` (default flags) marks fields that have a default as required. That suits
the app: it always holds full definitions the server returned, and new criteria are built by
the constructors in `cohort.ts` with every field filled.

`web/src/types.ts`:

### The transport seam (`web/src/transport.ts`)

```ts
export interface OptionsQuery { q?: string; field?: string; parent?: string; limit?: number }

export interface Transport {
  apply(definition: Definition, op: Operation): Promise<ApplyResult>;   // POST /api/apply   | MCP apply_op
  count(definition: Definition): Promise<CountResult>;                  // POST /api/cohort  | MCP count
  pivot(definition: Definition): Promise<PivotResult>;                  // POST /api/pivot   | MCP pivot
  options(query: OptionsQuery): Promise<Options>;                       // GET /api/options  | MCP search_vocabulary
}

export class TransportError extends Error {
  constructor(message: string, readonly status: number, readonly retryAfter: number | null = null)
}

export function fetchTransport(fetchImpl: typeof fetch = fetch): Transport
export function errorMessage(status: number, body: unknown): string
```

- Every request is same-origin and relative (`/api/...`), `credentials: "same-origin"`,
  `accept: application/json`; POSTs send `content-type: application/json` and
  `JSON.stringify(body)`. `count`/`pivot` post the definition itself; `apply` posts
  `{definition, op}`; `options` builds the query with `URLSearchParams`, omitting unset keys.
- A non-2xx response throws `TransportError(errorMessage(status, body), status, retryAfter)`.
  `errorMessage`: FastAPI's `{"detail": "<string>"}` (400, 401, 429) gives the string; a 422
  `{"detail": [{loc, msg}, ...]}` gives `` `${loc.slice(1).join(".")}: ${msg}` `` for the first
  entry (`loc[0]` is `"body"`/`"query"`); anything else gives `` `request failed (${status})` ``.
  `retryAfter` is `Number(headers.get("retry-after"))` on 429, else `null`. A network failure
  throws `TransportError("network error", 0)`.
- Components never call `fetch`; they receive a `Transport` through `App`'s props. The MCP App
  (decision 10) will add a second implementation of the same interface.
- Login: `/` and the assets are behind `RequireUser`, so under `--auth password` the browser
  shows its Basic prompt when the page loads and resends the credentials on the same-origin
  fetches. A 401 from a fetch shows "Your login has expired; reload the page."

### `/api/options` filters (backend change)

The builder needs every value of a small field (sex, vendor, assay class, age band) and the values
under a parent (a gene's protein changes, a marker's calls and clones, a biomarker's calls)
without the user typing. `Vocabulary.search` today returns `[]` for an empty `q` and filters only
by substring.

```python
# cohort/vocabulary.py
def search(self, q: str, limit: int = 20, field: str | None = None,
           parent: str | None = None) -> list[VocabEntry]:
    """Entries whose value contains q (case-insensitive), optionally only of one field and one
    parent. An empty q returns nothing unless field is given (then: that field's values)."""
```

- `q` stripped and lower-cased as today; `len(q) > 100` → `[]`; empty `q` and `field is None` →
  `[]`; `limit` clamped to 1–50 as today.
- Filter `e.field == field` when `field` is given and `e.parent == parent` when `parent` is
  given (exact, case-sensitive: parents are stored as the mart writes them, genes upper-case).
- Same rank as today: exact value, then prefix, then more patients, then value.
- `app.py`: `run_options(q: str, limit: int = 20, field: str | None = None, parent: str | None = None)`
  passes both through; `GET /api/options` gains `field: str | None = None, parent: str | None = None`
  query parameters; the MCP tool becomes
  `search_vocabulary(q: str, ctx: Context, limit: int = 20, field: str | None = None, parent: str | None = None)`
  with its docstring adding "Give `field` (e.g. `alteration.aa`) and optionally `parent` (e.g.
  `KRAS`) to list one field's values; `q` may then be empty." An unknown field returns no entries
  (no error).
- Privacy: unchanged. Entries are the already-floored vocabulary (values held by fewer than 5
  patients are never present) and carry no counts. Listing a field returns nothing typing could
  not already enumerate, ranked as search already ranks.

### State, operations and the server round trip (`App.tsx`)

The browser's state is the definition and its versions. It never builds SQL and never edits a
definition locally: every edit is an `Operation` sent through `transport.apply`, and the
definition the server returns (normalised, vocabulary-checked) becomes the new version.

```ts
export interface Version { n: number; definition: Definition }
export interface History { versions: Version[]; current: number }   // index into versions
export const EMPTY: Definition   // version 1, name "", empty population (years null), [] criteria, scope "patient", [] breakdown, pivot null
export const HISTORY_KEY = "uccc-discover-history";
export const MAX_VERSIONS = 50;
```

- `edit(op)`: `transport.apply(current, op)` → `pushVersion(history, result.definition)` → save
  to `localStorage[HISTORY_KEY]` → set `location.hash` with `history.replaceState` to
  `shareHash(definition)` → `refresh()`. A `TransportError` shows its message in an
  `role="alert"` banner above the builder and leaves the version unchanged (the 400 message names
  the field, e.g. `criteria.c1.aa: 'Q61X' is not in the vocabulary for KRAS`).
- `refresh()`: `transport.count(current)`; and, if the Pivot tab is open and `current.pivot` is
  set, `transport.pivot(current)`. A request sequence number drops responses that arrive after a
  newer request. While waiting, the answer column keeps the previous result with
  `aria-busy="true"`. A 429 shows "Too many queries; try again in N s." Results are never written
  to storage.
- Version select (`<select aria-label="Version">`, options `v1` … `vN`): choosing one sets
  `current` to it (no new version) and refreshes; the next edit appends after the newest version.
  Versions keep their number when the oldest is dropped past `MAX_VERSIONS`.
- Load: if `location.hash` holds `#d=…`, decode it (`readShareHash`), normalise it with
  `transport.apply(decoded, {op: "rename", name: decoded.name})`, and push it as a new version
  unless it equals the current one. A hash that does not decode or that the server rejects shows
  "This link does not hold a valid cohort: <message>" and continues with the stored history (or
  `EMPTY`). Without a hash, the stored history (or `[EMPTY]`) is used. Then
  `transport.options({})` once for `years`, `cut_points` and `min_cell`, then `refresh()`.
- Name: a text input in the top bar; on blur or Enter, if it changed, `edit({op: "rename", name})`.

### Share link

The share link is the page URL with `#d=<base64url(UTF-8 JSON of the definition)>`, kept in the
address bar for the current version. The top bar shows the `cohort_id` returned with the latest
result and a "Share link" button that copies `location.href` with `navigator.clipboard.writeText`
when `navigator.clipboard` exists, and otherwise (plain-HTTP tailnet address: not a secure
context) reveals a read-only, pre-selected `<input>` holding the link. The fragment never reaches
the server, so links do not enter access logs.

**Deviation from the issue ("share link by `cohort_id`").** A `cohort_id` is a one-way hash; with
no store until the Postgres issue, a link holding only the id could not be opened. The link
carries the definition and the page shows the id beside it; `/c/<cohort_id>` comes with saved
cohorts. Definitions hold no patient data, so the link is safe to send.

### Layout and components (§3.3)

CSS grid, `web/src/styles.css`. Wide (≥ 1200 px): builder `minmax(18rem, 24rem)`, answer `1fr`,
assistant `minmax(14rem, 18rem)`. Below 1200 px the assistant column is not rendered (it is
empty); below 800 px builder and answer stack. Readable at 1280 × 800 with no horizontal
scroll. Every wide piece of the answer column scrolls inside its own focusable container, never
the page: pivot and breakdown tables render through `GridTable`, which wraps the table in a
`.table-scroll` (`overflow-x: auto`) with sticky row headers, and the accrual chart's `.bars`
is itself `overflow-x: auto` (`tabIndex={0}`), since it draws one column per year of data.

**Top bar** (`<header>`): name input (`aria-label="Cohort name"`, placeholder "Untitled
cohort"), version select, `cohort_id` in `<code>`, "Share link" button.

**Builder** (`<section aria-labelledby>` "Population" and "Criteria"):

- Population chips: one chip per value in `oncotree`, `organ`, `sex`, `age_band`, `vendor`,
  `assay_class`, plus a years chip. Each chip is `<span>` text + `<button aria-label="Remove
  NSCLC">×</button>`; removing sends `set_population` with the value dropped.
- "+ sex", "+ age", "+ vendor", "+ assay" buttons open a checkbox group listing
  `transport.options({field: "population.<dim>", limit: 50})` values; "+ tumor type" and "+ organ"
  open a `Typeahead` restricted to that field. Each change sends one `set_population`.
- Years: two `<select>`s (From, To) over `options.years`, with "All years" (sends `years: null`).
- Criteria heading says "(all must match)". Each criterion is a card (`<article>`): its
  `criterionLabel`, an "Edit" button, an "Or…" button and a "Remove" button
  (`remove_criterion`). Edit opens the card's editor inline; Save sends `update_criterion`.
  Editors, per kind, use only allowed values:
  - alteration: class checkboxes (mutation, amplification, loss, fusion); protein changes as
    checkboxes from `options({field: "alteration.aa", parent: gene, limit: 50})` (shown when
    there is one gene and class is mutation or any; listed most common first, without counts);
    tier checkboxes (pathogenic, likely pathogenic checked by default; VUS, unclassified opt-in).
  - biomarker: call checkboxes from `options({field: "biomarker.call", parent: name})`, or for
    TMB a "at least" `<select>` over `cut_points["biomarker.TMB"]`; choosing one clears the other.
  - ihc: clone `<select>` from `ihc.clone` (parent marker, "any clone" = null); calls from
    `ihc.call`; or measure (TPS / CPS) + "at least" over `cut_points["ihc.<measure>"]`.
  - expression: "at least" percentile over `cut_points["expression.percentile"]` or "measured".
  - specimen: site type and site checkboxes from their fields; purity over
    `cut_points["specimen.purity"]`.
  - actionability: the three evidence checkboxes, offering only values present in
    `options({field: "actionability.evidence"})`.
  - any_of: the members' labels, each with remove (when two remain, removing one turns the card
    back into that single leaf via `update_criterion`).
- "Or…" opens a `Typeahead`; the picked entry's `newCriterion` (without `id`) is OR-ed in with
  `update_criterion`: a leaf becomes `{kind: "any_of", of: [leaf without id, new]}`, an `any_of`
  gets the member appended (max 8; the button is disabled at 8). This makes questions 4, 6 and 7
  buildable by clicking.
- "Add criterion" is a `Typeahead` over the whole vocabulary (`options({q, limit: 20})`, 150 ms
  debounce, at least 1 character). Each option shows its value and a field label ("Gene",
  "KRAS protein change", "IHC marker", "PD-L1 call", "Tumor type (OncoTree)", …), no counts.
  Static entries "Biomarker TMB", "Biomarker MSI", "Biomarker LOH" are added client-side when the
  query is a prefix of the name (the vocabulary searches values, not biomarker names); picking one
  adds `{kind: "biomarker", name, call: [], at_least: null}` ("tested"). Picking a `population.*`
  entry adds it to the population; anything else sends `add_criterion` with `newCriterion(e)`.

`Typeahead` is a WAI-ARIA combobox: `<input role="combobox" aria-expanded aria-controls
aria-activedescendant aria-autocomplete="list">` with a `<ul role="listbox">` of `<li
role="option" aria-selected>`; ArrowDown/ArrowUp move, Enter picks, Escape closes, Home/End jump
(`comboKey`). Mouse pick works too. An empty result shows "No matching values (values held by
fewer than 5 patients are not offered)."

**Answer** (`<main>`):

- `Count` component: `null` renders `<span class="suppressed" title="Fewer than 5 patients, or
  hidden so that a small count cannot be worked out by subtraction">&lt;5</span>` (with
  `min_cell` from the result), never `0` or blank; numbers use `fmtCount`.
- Cards: **Patients** (`patients`, plus `reports` "in N reports"); **Accrual a year**
  (`accrualPerYear(patients, window)` where the window is `population.years ?? options.years`,
  one decimal, "–" when patients is null) with the tier badge (`tierFor`); **Share of
  population** (`pct(patients, denominator)`, "–" when null) with the denominator named under it:
  "of {fmtCount(denominator)} patients in {populationLabel}". An `aria-live="polite"` region
  announces "N patients" (or "fewer than 5 patients") after each refresh.
- **Funnel**: an ordered list, one row per `funnel` step: label (step 0 = `populationLabel`, step
  k = "∧ " + `criterionLabel` of that criterion id), the count (`Count`), and a bar whose width is
  `patients / funnel[0].patients`. A null step draws a hatched bar of fixed short width labelled
  "<5". A legend under it explains "<5".
- **Loosen**: when `patients` is null or `loosen` is non-empty, a box under the cards: "Too few
  patients to show." then, for each `loosen` entry, "Drop {criterionLabel} → {fmtCount} patients"
  with a "Drop" button that sends `remove_criterion`. With `patients` null and `loosen` empty:
  "No single criterion, dropped, brings this cohort to 5 or more."

### What leaves the de-id file, and the small-cell rule

The app adds no output path. Every number it shows is a field of a `CountResult` or
`PivotResult` from `POST /api/cohort` / `POST /api/pivot`, already through `suppress.py` (floor of
5, secondary suppression on every line and both pivot axes, floored funnel deltas, the whole-cohort
rule, the `loosen[]` clearance rule). The app does no arithmetic that could undo suppression: the
only derived numbers are `pct(patients, denominator)` and `accrualPerYear`, both of shown values
(the nested-set ratio §3.6 already accepts), and both are "–" when an input is null. A null is
always shown as "<5", never `0`, blank or an estimate, and the app never computes a hidden value
from totals. Vocabulary values come from the floored vocabulary with no counts. Nothing is
stored in the browser but definitions. Rate limiting, audit and login are the server's (#35);
the app adds no endpoint. `research_id` and `report_id` never reach the app.

The one backend change (`field` / `parent` on options) returns only floored vocabulary values
(see above), on both surfaces.

## Risks

- **Two generated files to keep in sync.** A model change in `cohort/` or `app.py` now needs
  `bun run gen`. Both pytest and `typecheck` fail loudly until it is run, and the message says so.
- **TypeScript pinned to 5.9.3** because of `openapi-typescript`'s peer. When it supports
  TypeScript 7, both move together.
- **Share links hold the definition.** They are long-ish (a few hundred characters for ten
  criteria) and change when the definition changes; links break if a later schema version
  rejects them (the load path then says so). Short links by `cohort_id` need saved cohorts.
- **`localStorage` versions** are per browser and per origin, and vanish with site data. Saved
  cohorts (Postgres) replace them.
- **Clipboard on plain HTTP.** The tailnet dev URL is not a secure context, so the copy falls back
  to a selected text field.
- **One count per edit.** Each click is one `count` (plus `pivot` when that tab is open) against
  the 60-a-minute limit; brisk editing can hit 429, which the app reports with the wait time.
- **`<5` for secondary suppression.** A null may be a cell hidden only to protect a neighbour and
  could be larger than 4. The API deliberately does not say which; the app labels every null "<5"
  as the issue asks, and its tooltip and legend say "fewer than 5, or hidden so a small count
  cannot be worked out by subtraction".
- **Listing a field's values** (`field`/`parent`) shows their order by patients, as search
  already does; no counts, and only floored values.
